# 每周维护流程

建议每周固定 30 分钟维护一次。目标不是整理得完美，而是让知识库持续流动。

## 1. 清理 Inbox

检查 `00_Inbox/` 中的新内容：

- 没价值：删除或归档。
- 项目相关：移动到 `10_Projects/`。
- 外部资料：移动到 `30_Resources/`。
- 有独立价值：提炼到 `40_Notes/`。

## 2. 提炼原子笔记

对重要资料至少写一张原子笔记：

- 这条信息说明了什么？
- 它能解决什么问题？
- 它和已有知识有什么关系？
- 未来可以在哪些场景复用？

## 3. 补充连接

为新笔记补齐：

- `tags`
- `source`
- `related`
- `moc`

同时更新相关 MOC。

## 4. 处理资料文件

PDF、代码、drawio 不要孤立存放。重要资料应有对应的 Markdown 索引说明：

```text
原始资料：30_Resources/PDFs/example.pdf
索引笔记：30_Resources/PDFs/example.md
沉淀笔记：40_Notes/YYYYMMDDHHmm-example核心观点.md
```

## 5. 标记输出机会

如果某个 MOC 下已经积累 5 到 10 张相关笔记，考虑输出到：

```text
60_Outputs/
```

输出形式可以是文章、报告、方案、清单、教程或复盘。
